# skil

用于保存和维护 AI 软件开发协作规则。当前优化版本为 [0.0.1](0.0.1/)，基于原始三份文档及 OpenAI 官方指导整理。

## 0.0.1 文档

| 文件 | 职责 |
| --- | --- |
| [AGENTS.md](0.0.1/AGENTS.md) | 加载入口、任务范围、工具使用、已有修改保护、状态保存与恢复 |
| [ALL_AI_CODE.md](0.0.1/ALL_AI_CODE.md) | 设计决策、职责边界、完整修复、验证和结果沟通 |
| [AI_PROJECT_RULES.md](0.0.1/AI_PROJECT_RULES.md) | 交付方式、文件命名、项目变更记录 |

原始根目录文件保留原名和原内容。版本目录是用户指定的发布组织方式；目录内文件使用稳定名称，不带下载产生的数字后缀。

## 使用方式

本版本是配套规则文档，不是三个已经安装的 Skill。仅上传到 GitHub 或保存在 `0.0.1` 目录，不会使其在所有聊天或其他项目中自动启用。

- 在目标项目采用时，将三份文件作为同一套规则使用。目标项目已有 `AGENTS.md` 时，合并适用规则与加载入口，保留该项目的具体命令和约束，不直接覆盖原文件。文件位置改变时同步调整相对链接。
- 在会话中显式使用时，指定这套版本并要求读取入口及两份关联文档。目标环境仍按自身权限和指令发现机制执行。
- 在本仓库根目录工作时，原始根目录 `AGENTS.md` 仍在原位置；`0.0.1/AGENTS.md` 不会仅因存在于子目录就自动替换根目录规则。请明确选择版本，避免误以为归档即已切换。
- 部署到实际项目后，补充或保留真实的启动、测试、构建命令及项目特例。本套通用文档不猜测具体项目配置。
- 如以后需要可发现、可安装的 Skill，再为具体重复流程建立包含 `name`、`description` 的 `SKILL.md` 和必要资源；不要仅把普通 Markdown 文件改名就声称已经安装。

## 审计结论与修改对应

| 原问题 | 0.0.1 的处理 |
| --- | --- |
| 主规范引用名称不一致，入口未明确加载其余文件 | 使用准确的相对链接，声明文件职责、读取时机和冲突处理 |
| 固定十步流程容易把分析任务变成实施任务 | 按任务类型选择步骤，记录更新由实际变更触发 |
| 工具名称与数量阈值替代实际判断 | 根据未核实事实和表达需要触发，检查能力并提供回退 |
| 修改前画图与“只画已实现链路”不协调 | 区分现状、拟议方案和最终实现，要求同步受影响的项目图 |
| 状态协议只有保存，没有恢复和过期判断 | 核对稳定项目标识、分支、提交和工作区，区分事实与计划 |
| 模块化规则重复，拆分线索容易变成硬阈值 | 工程规则集中维护；拆分以职责、状态与依赖的实际收益为准 |
| 完整修复的范围与同根证据不够具体 | 保留全链路修复，增加代码路径、契约、复现或测试证据要求 |
| 验证失败缺少分类和结束条件 | 区分本次回归、既有失败、环境阻塞；限制无依据的重复验证 |
| README、任务书和状态容易重复保存相同内容 | 明确各类记录职责和引用关系，保留一个权威变更入口 |
| 补丁独立运行的要求不适合基线交付 | 按明确基线完整应用，覆盖新增、删除、重命名和必要迁移 |
| 常规决策易停顿、工作区已有修改保护不明确 | 持续推进已授权任务，保留无关改动，说明具体阻塞 |

保留的核心约束：最合适的设计优先；按真实职责组织模块；状态、业务规则和副作用保持明确归属；修复全部已确认受影响链路；保护兼容性；验证证据与完成声明一致。

## 验证与适用边界

本次已完成本地相对链接、UTF-8 文本、旧引用残留及文件结构检查；独立一致性审查后补齐外部写入结果不明时的核查与重试条件。

另一个独立审查者仅依据新版三份规则和给定情境，在未读取本 README 的情况下完成六项执行决策推演。下表记录其实际判断；没有在这些情境中修改项目、运行构建或测试、创建提交。

| 情境 | 推演中的执行判断 |
| --- | --- |
| 两处文档错字，项目要求 doc-lint，另有用户业务代码改动 | 只修改并提交本次文档；从真实配置确定命令，通过规定检查；保留无关改动 |
| 列表入口已修，标签入口仍有同根缺陷，另有无关颜色问题 | 继续修复共享清理链及受影响入口；颜色问题记录后续，不顺带修改 |
| 锁定版本的第三方 API 签名错误，Context7 不可用 | 核对安装版本、类型声明和对应官方文档，继续修复；不自动升级依赖 |
| Windows 专用行为，仅 Linux 静态检查和模拟测试通过 | 报告代码与已完成检查，明确 Windows 实际验收待完成，不宣称全面验证 |
| 旧状态指向旧分支，当前有新提交及未提交修改 | 对照当前目标、分支和改动恢复；不自动切回旧分支或沿用已过期验证 |
| 仅分析四个文件的简单常量改名影响 | 交付只读分析；不实施改名或提交，不按文件数量机械画图 |

六项判断与本版本的任务边界和完成声明要求一致。这是单次定性评估，没有旧版对照或真实项目行为回归，不能据此量化速度、成功率或模型性能提升。后续应在相同模型、工具和项目条件下比较旧版与新版的实际结果、越界改动、无必要暂停和重复调用；这些样例不是每次开发都必须执行的流程。
