# Figma 设计交接与代码接入

本文件提供通用工作流程及填写规范，不记录某个项目已完成的设计。采用时以真实项目资料填写 [状态记录](figma-state.json)，并选择或替换 [token 示例](figma-tokens.json)。工程与交付规则分别归属 [Code](../../../Code/0.0.1/ALL_AI_CODE.md) 和 [项目记录规则](../../../Code/0.0.1/AI_PROJECT_RULES.md)。

## 项目配置与前置

| 信息 | 填写要求 |
| --- | --- |
| 项目身份 | 实际仓库、分支、基准提交；纯设计任务无仓库时注明不适用 |
| 需求依据 | 任务书、接口契约、用户确认及其版本/位置 |
| 范围 | 产品类型、用户角色、任务路径、包含与排除事项 |
| 实施环境 | 现有框架、组件库、服务接口、目标平台及版本；未确定项标为待确认 |
| 设计身份 | 实际文件 URL、file key、页面和节点 ID；未创建则不填造假 ID |
| 授权与阶段 | 当前授权范围、设计/实现阶段前置、已有审批依据；不继承其他项目历史授权 |
| 验收条件 | 目标窗口、缩放、主题、语言、数据规模及真实业务路径 |

## 执行与交付

| 环节 | 产物 | 完成依据 |
| --- | --- | --- |
| 需求与交互 | 页面清单、角色矩阵、主要及异常任务路径 | 与真实需求和权限契约对应 |
| 实现可行性 | 组件复用、组合方式、缺口、候选栈 | 明确候选与已安装内容，不提前引入依赖 |
| 视觉方向 | 字体、层级、密度、颜色与语义 token | 用户确认依据和真实内容可读性 |
| 可编辑设计 | 变量、组件、页面实例、状态与原型 | 实际节点检查和截图证据 |
| 代码接入 | 组件映射、主题绑定、真实接口 | 前置满足且处于已授权实施范围 |
| 验证与验收 | 各项检查结果和未验证限制 | 证据对应具体设计/代码版本与环境 |

先完成一条代表性路径及实现可行性检查，再按授权范围展开。使用 Foundations、Components、Patterns、Screens、Review/Archive 等分组时可按项目调整。确认过的外观需要映射到实际组件和主题，不能被默认主题覆盖。

## 设计覆盖

从项目真实任务派生页面和状态，不预设行业或固定角色。覆盖适用的输入校验、权限、异步反馈、取消/返回、数据刷新、冲突、会话和恢复行为；是否支持离线、分页、导出等以项目契约为准，不自动新增功能。

明确长文本、窄窗口、大数据量、焦点、键盘和滚动策略，避免裁掉必要数据。每条原型连接记录起点、触发、目标、返回定位、输入/滚动保留和重置规则；示例操作的静态限制单独标注。

设计反馈影响基础变量或主组件时，同步检查实例、业务页和导出文件。历史稿与当前实施依据分开标注，不沿用已否决方向，不擅自删除已有设计。

## 交接字段

| 类别 | 必须记录的实际信息 |
| --- | --- |
| 页面 | 名称、角色/任务、页面与根节点 ID、状态、设计链接 |
| 组件 | node ID、组件名、属性/变体、代码路径、导出名、映射状态 |
| 动作 | 触发、目标、数据来源、真实接口、权限、异常与恢复语义 |
| 变量 | 集合与模式、类型、值或别名、作用域、实际代码映射 |
| 资源 | 来源、版本、许可、用途、修改与分发方式、核查证据 |
| 复核 | 对应版本、环境、方法、结果、限制及下一项 |

未实现的代码路径和接口标为 proposed，不作为已接通证据。实际映射使用 implemented/verified 等明确状态，并附验证依据。Code Connect 不可用或不适配时采用人工映射表，不伪称自动同步。

## 状态 JSON 的使用

figma-state.json 是 schemaVersion 2 的未配置模板：身份字段为 null、项目列表为空、检查为 not_run。空值表示尚无项目事实，不能当成功状态或用来跳过检查。沿用顶层页面、组件、属性、图标、计数、屏幕、原型、审计、评审与归档职责；移除了具体项目实例。

填写约定：pages/screens 以业务标识映射实际节点；components 记录节点、属性与代码映射；prototypeConnections 记录 source、trigger、destination、返回/保留规则；verification 每项包含 status、evidence 和 environment。状态可为 not_run、passed、failed、blocked 或有理由的 not_applicable。counts 未测量前保持 null，不能以 0 冒充检查结果。业务真实验收与视觉验收分别记录。

模板结构不同于旧项目导出快照；如有消费脚本，先按 schemaVersion 适配并验证，不能直接覆盖运行中项目状态。项目历史由原项目与 Git 历史保留，模板不承载旧验收结论。

## Token 示例的使用

figma-tokens.json 保留可选的颜色、尺寸、字体数值和别名关系，status 为 example，不能当作已批准主题或真实 Figma 导出。集合、模式、变量及文字样式的 id 是 example 命名空间的本地引用标识，不得传给 Figma API；实际项目应使用真实导出数据替换。

选择主题前核对用户要求、品牌、可读性及组件栈。CSS codeSyntax 只是 Web 候选映射；其他技术栈使用其实际主题机制，不强制 CSS。先解析别名，再检查模式、类型和作用域；变量映射、字体和许可需在目标环境验证。

## 验证与续接

1. 读取已授权节点上下文、截图及变量，核对组件引用、原型目标和权限路径。
2. 接入阶段按 Code 职责边界绑定真实数据、接口和副作用；模拟输入和占位结果不能满足真实业务验收。
3. 在相同窗口、主题、内容和状态下对照设计与运行界面，分别记录结构、截图和原型回放结果。
4. 分别执行项目要求的静态检查、构建、自动测试及目标平台实机验收。Windows 任务记录实际 DPI、窗口、键盘和安装条件，未执行项明确说明。
5. 更新状态中的基准、已完成事实、限制和下一步；只复查受变更影响或仍有具体风险的范围。设计交接保存证据，根 README 或项目既有变更机制保留唯一权威变更记录。
