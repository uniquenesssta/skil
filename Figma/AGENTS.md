# Figma 设计与代码交接规则

适用于需要 Figma 设计、设计系统维护或设计到代码交接的项目。本文件是可采用的规则入口，不代表已安装 Skill、已创建设计文件或已获外部写入授权。仅编辑本套规则时，规则是维护材料。

## 1. 加载与规则归属

1. 采用本套规则时，先读取 [Code 通用入口](../Code/0.0.1/AGENTS.md)，并按入口读取 [工程规则](../Code/0.0.1/ALL_AI_CODE.md) 与 [交付和记录规则](../Code/0.0.1/AI_PROJECT_RULES.md)。这里的 `Code/` 是规则目录，不是目标项目的源码路径。
2. Code 管理任务范围、授权、工具、续接、职责拆分、兼容性、完整修复、验证和交付；本文件只补充 Figma 设计与交接要求，不重复建立另一套工程规则。
3. 读取目标项目的现有指令、需求依据、技术栈、接口契约、权限定义及 [设计交接流程](docs/design/figma-handoff.md)。目录迁移或单独采用时，更新规则入口路径；目标项目已有 AGENTS.md 时合并适用入口，不覆盖已有约束。
4. 遵守平台指令层级及 Code 中的冲突处理规则。同一事项以用户最新明确纠正为准，并同步修改设计、实现和验收标准。

## 2. 项目适配与工作范围

- 核对实际仓库、当前分支、提交和已有改动。复用用户指定的位置；不预设分支名，不因采用本文件另建分支或创建 Figma 文件。
- 从当前需求确定产品类型、目标用户、角色权限、业务流程、技术栈和目标平台，不固定行业、角色名称、框架或后端语言。
- 在 figma-state.json 中填写真实项目身份、依据、范围、授权和验收条件。未确认字段保留 null 或待确认状态；模板中的空值不是缺失检查的豁免，也不是完成证据。
- 区分设计、原型、实现、验证与用户验收。按已授权范围持续推进；既有授权仍有效时不重复询问，历史记录和示例本身不产生新授权。
- 先核对实际阶段前置再接入代码，不预设阶段编号。设计工作不自动触发依赖安装、业务改造或下一阶段；交接时保护最新实现及其他分支内容。

## 3. 设计能力的选择

按任务需要选择实际可用的技能，来源参考见 [交接流程](docs/design/figma-handoff.md#skill-来源与适用边界)。名称和上游链接不代表已安装、已执行或已获得权限。

1. 需求与交互：可使用 UI/UX Pro Max，明确用户任务、信息架构、输入、错误反馈、可访问性与键盘操作；候选建议必须适合实际产品。
2. 实现可行性：核对现有组件库、框架、可复用组件和定制缺口。仅在技术栈适配时采用 shadcn 指南，不因工具名称强制安装框架。
3. 视觉方向：可使用 Hallmark，确定字体、层级、密度、颜色和一致性；以用户确认方向为准，不固定配色、字体、布局或尺寸。
4. 可编辑设计：可参考 Open Design 的组织方法，实际读写使用当前环境的 Figma 专用技能及工具。
5. 审美复核：先确认 Taste 等技能的适用范围；不适用的完整流程不执行，不把参考意见说成完整验收通过。
6. 代码交接：按实施授权和实际技术栈读取设计上下文、截图、变量及组件，接入真实功能与数据。

## 4. Figma 工作要求

- 只使用当前任务明确指定或授权创建的文件。登记真实 file key、页面、node ID 与可打开链接，不沿用模板或其他项目的资源身份。
- 操作前加载当前环境要求的 Figma 技能：创建、写入、组件系统、设计到代码分别按其适用流程执行。不编造工具结果。
- 变量承载语义颜色、字体、间距、圆角等；组件承载属性、变体与状态；页面以实例组合。合理使用 Auto Layout 和 resizing，避免不可维护的绝对坐标堆叠及整页栅格化。
- 按真实业务覆盖角色路径、加载、空、失败、禁用、焦点，以及适用的会话、权限、并发、离线、恢复等状态。无适用含义的状态注明原因，不机械补画；离线规则由项目契约确定。
- 原型登记触发、结果、返回定位、滚动与输入保留、取消和重置规则。示例数据明确标注，不把模拟操作当真实交易或持久存储。
- 设计变更同步检查基础变量、主组件、实例、页面、原型与导出记录。用户否决的版本明确归档，不继续作为实现依据，不擅自删除用户稿件。

## 5. 代码交接补充

- 代码组织和工程验证遵循 Code；根据真实依赖及版本核对组件 API，复用已有组件并保护定制，不用组件库默认主题覆盖已确认设计。
- 用语义 token 对接实际主题层，用节点与组件映射记录代码路径、导出名、属性、状态及真实数据接口。Code Connect 仅在可用且适配时采用，人工记录不得声称自动同步。
- 页面负责展示和交互，业务编排、持久化、权限及外部服务按职责归属。业务权威规则遵循现有契约，不在 UI 复制计算和第二套状态；精确数值采用项目规定的数据类型与精度。
- 按角色契约控制数据和动作；隐藏控件不能替代服务端或可信层鉴权。幂等、版本、未知结果核查及恢复按实际接口处理，不硬编码业务结果。
- 不放宽权限、沙箱、命令或数据访问边界来掩盖错误。设计中的占位接口与候选路径必须明确标注，实施验收必须验证真实功能链路。

## 6. 验证与记录

按实际范围分别记录设计结构、截图复核、原型回放、静态检查、构建、自动测试、目标环境运行和用户验收结果，不能相互替代。Windows 项目明确实机版本、窗口与 DPI 条件；未在 Windows 运行不得宣称实机通过。提供操作命令时优先使用 PowerShell。

设计证据与节点映射放在交接文档和状态文件；项目变更遵循 Code 的唯一权威变更记录规则，默认根 README，已有正式变更机制则沿用。交接记录不替代项目变更日志或任务验收。外部操作回执不明时先核对目标，避免重复写入。
